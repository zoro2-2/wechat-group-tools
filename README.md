# 微信群工具集（WeChat Group Tools）

Windows 下读取**本机微信（4.x）**群成员与微信号的两个小工具，纯只读、不联网。

> ⚠️ **重要声明**：本项目仅供**导出自己设备上的个人数据**用于备份与整理。
> 批量添加好友违反《微信个人账号使用规范》，可能导致**功能限制或封号**。
> 使用本项目的任何后果由使用者自行承担。详见 [免责声明](#免责声明)。

---

## 包含什么

| 程序 | 作用 |
|---|---|
| `群好友助手.exe` | 读取群成员名单（群号 / 微信号 / 昵称），支持导出 CSV、按群筛选、群重命名、半自动辅助添加 |
| `取微信号.exe` | 一键读取全部微信号（wxid），可复制或导出 CSV |

两个程序都是**单文件、免安装**，`csc.exe` 直接编译，不需要 .NET SDK。

---

## 功能

### 群好友助手

- **读取群成员**：从微信进程内存解析 `chatroom_member` 关系表，得到「群 → 成员」映射
- **按群筛选**：下拉框手动选择要查看的群（按人数排序）
- **导出 CSV**：群号、微信号、昵称，UTF-8 带 BOM，Excel 直接打开不乱码
- **群重命名**：给群起个本机可见的名字（存 `%APPDATA%\群好友助手\group-labels.tsv`）
- **半自动添加**：勾选成员后逐个复制微信号并置前微信，你粘贴搜索→添加→点「下一个」；
  带进度记录与断点续传（`add-log.tsv`），**不自动点击微信任何按钮**
- **OCR 读屏**（实验性）：用 Windows 自带中文 OCR 读取界面上的群名/人数

### 取微信号

- 一键提取内存中出现的全部 `wxid_*`（实测单次可提取 700+ 条）【这也是现在面临的一个问题，暂时无法识别其他形式的微信号，需要后续改进】
- 复制全部 / 导出 CSV
- 微信**不必在前台**，最小化也能读

## 编译

### 环境要求

- Windows 10 / 11（64 位）
- .NET Framework 4.x（系统自带）
- **不需要** Visual Studio 或 .NET SDK，只要有 `csc.exe`

### 一键编译

```cmd
build.cmd
```

或手工：

```cmd
set CSC=C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe

% CSC% /nologo /target:winexe /platform:x64 /codepage:65001 ^
  /win32manifest:src\app.manifest /win32icon:app.ico ^
  /out:dist\群好友助手.exe ^
  src\GroupHelper.cs src\AssemblyInfo.cs ^
  /r:System.Windows.Forms.dll /r:System.Drawing.dll

% CSC% /nologo /target:winexe /platform:x64 /codepage:65001 ^
  /win32manifest:src\app.manifest /win32icon:app.ico ^
  /out:dist\取微信号.exe ^
  src\GetWxid.cs ^
  /r:System.Windows.Forms.dll /r:System.Drawing.dll
```

> `/codepage:65001` 必须加，否则中文字符串会乱码。

## 使用

### 群好友助手

1. 打开并登录微信，**先在微信里打开目标群**（建议再点开一次「群成员」面板并滚几屏）
2. 右键 `群好友助手.exe` → **以管理员身份运行**
   （微信以管理员权限运行，不提权读不到它的内存）
3. 点「读取当前群成员」，等待 10–60 秒
4. 在下拉框里**手动选择**要查看的群
5. 勾选成员 → 「导出勾选」/「导出本群全部」

**读取加速**：程序会把数据累积缓存到 `%APPDATA%\群好友助手\pages-cache.tsv`，
所以**读得越多、覆盖越全**。第二次以后通常十几秒完成。

### 取微信号

1. 打开微信（登录即可，不必在前台）
2. 双击 `取微信号.exe`（自带管理员清单）
3. 点「读取微信号」，等待约 20 秒

## 技术原理

微信 4.x 的数据库是 **SQLCipher v4** 加密的（页大小 4096，保留区 80 字节 = IV 16 + HMAC-SHA512 64）。
密钥不存在于内存中的明文形式（我们做过 7 亿次候选密钥扫描，全部失败），
但微信用来加速查询的**解密后数据页会常驻进程内存**。

本项目只读这些已解密的内存页，按 SQLite 页格式与记录格式还原出行数据：

```
扫描内存 → 找页头(0x0D 表叶 / 0x0A 索引叶) → 校验页结构
        → 解析 varint + serial type → 还原列 → 按表关系拼接
```

### 数据可靠性

| 字段 | 可靠性 | 原因 |
|---|---|---|
| 群号 `xxx@chatroom` | ✅ 可靠 | 微信真实内部 id |
| 微信号 `wxid_*` | ✅ 可靠 | 每个都是真实账号 |
| **某人在某群** | ⚠️ **近似** | 微信每个数据库有**独立的 id 编号空间**（`contact.db` 的 `Name2Id`、`message.db` 的 `ChatName2Id` 等），而内存页交错存放、无法判断归属。实测 2287 个 id 中 1605 个（70%）存在跨库冲突 |
| 群名称 | ⚠️ 需手动 | 内存中无群名；用「重命名群」保存一次 |
| 昵称 | ⚠️ 部分 | 只有微信加载过的联系人（聊过天/翻过通讯录）才有 |

程序内置了四道校验来抑制脏数据：

1. 页面形状一致（该页每行都是同样列型）
2. **主导群占比 ≥ 70%**（`chatroom_member` 按 `(room_id, member_id)` 排序，一页里绝大多数行属于同一个群）
3. 主导 id 必须映射为 `@chatroom`
4. 成员 id 必须映射为 `wxid_*`（过滤消息 id、会话 id 等）

## 已知限制

- **成员归属不精确**：受跨库 id 冲突影响，人数可能偏多、可能混入其他群的人。界面统一标注「≈估算」
- **昵称覆盖低**：只有被微信加载过的人才有昵称；打开群成员面板后读取会明显提升
- **群名读不到**：微信主界面是自绘控件（Qt + MMUI），无可读控件树，只能手动命名
- **OCR 能力有限**：中文小字识别会出错（如把「招」识别成「摺」），放大 2 倍可显著改善
- **全自动点击不可靠**：微信的浮层一失焦就收起，且盲点坐标有误操作风险（可能点到退群等），
  因此本项目的「添加好友」采用**半自动**设计：程序只负责复制与置前，点击交给人

### 我们试过但没走通的路

| 方案 | 结果 |
|---|---|
| 32 字节裸密钥扫描内存 | 4.54 亿候选，未找到 |
| 16 字节裸密钥（AES-128） | 2.61 亿候选，未找到 |
| hex 字符串密钥（社区通解 `x'<64hex><32hex salt>'`） | 40 个库全扫，未找到 |
| DPAPI 解密 `key_info.db` | 24 条记录，格式为自定义 protobuf，非 DPAPI |
| OCR 读成员面板 | 面板内昵称本身被截断 |
| UI Automation 读控件 | 微信 4.x 主界面是自绘画布，仅暴露 3 个节点 |

结论：微信 4.2 的密钥派生方式与所有公开方案不同，进一步突破需要逆向 `Weixin.dll`。
