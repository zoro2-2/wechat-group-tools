# 技术说明

本文记录实现思路、关键实验数据与踩过的坑，供后来者少走弯路。

---

## 1. 目标环境的特殊性

| 项目 | 实测值 |
|---|---|
| 微信版本 | 4.2.0.13（`C:\Program Files\Tencent\Weixin\Weixin.exe`） |
| 权限 | **以管理员（High IL）运行** |
| UI 框架 | Qt 5.15.14 + 腾讯 MMUI 自绘 |
| 窗口类名 | `Qt51514QWindowIcon`，子窗口 `MMUIRenderSubWindowHW` |
| 数据库 | SQLCipher v4 加密（`contact.db`、`session.db`、`message_0.db` 等） |

### 1.1 权限坑（最重要）

微信以管理员权限运行，**非提权进程的合成输入会被 UIPI 静默丢弃**，但 `SendInput` 仍然返回成功。
表现为：`SetCursorPos` 返回 `FALSE` 且 `GetLastError()=0`，鼠标纹丝不动。

→ 任何涉及点击/键盘的工具**必须提权运行**。

### 1.2 UI Automation 完全不可用

UIA 只暴露 3 个节点（主窗口 + 一个渲染子窗口 + 空面板）。
整个界面是 Qt 自绘的画布，**没有任何可读控件**。

→ 想读界面文字，只能 OCR。

### 1.3 窗口标题会变

微信主窗口标题**跟随当前聊天变化**（例如变成群名）。
如果按标题 `"微信"` 找窗口，切换聊天后就找不到了。

→ 必须按**窗口类名**识别：`GetClassName` 包含 `QWindowIcon` 且不含 `SubWindow`，取面积最大的那个。

## 2. 数据库加密分析

### 2.1 参数确认

- 页大小 4096，保留区 80 字节 = IV 16 + HMAC-SHA512 64
- 页 1 结构：`salt[0:16]` + 密文 + `IV[PAGE-80:PAGE-64]` + `HMAC[PAGE-64:PAGE]`

### 2.2 密钥提取尝试（全部失败）

| 方案 | 规模 | 结果 |
|---|---|---|
| 32 字节裸密钥 + 4 种 reserve 变体 | 453,872,905 候选 | 未找到 |
| 16 字节裸密钥（AES-128） | 260,511,333 候选 | 未找到 |
| hex 字符串 `x'<64hex_key><32hex_salt>'` | 40 个库的 salt 全扫 | 未找到 |

扫描器本身有对照组验证（同期找到 `wxid_` 出现 20755 次、`SQLite format 3` 89 次），排除"扫不到"的可能。

### 2.3 `key_info.db` 线索

路径：`%USERPROFILE%\Documents\xwechat_files\all_users\login\<wxid>\key_info.db`

它是**明文 SQLite**：

```sql
CREATE TABLE LoginKeyInfoTable(
  user_name_md5 TEXT,
  key_md5 TEXT,        -- 实测为空
  key_info_md5 TEXT,
  key_info_data BLOB   -- 180 字节
)
```

`key_info_data` 不是 DPAPI（文件里搜不到 DPAPI 特征 `01 00 00 00 D0 8C 9D DF`），
而是 protobuf 风格的自定义结构：

```
0a a8 01  字段1，长度168
0b b5 17 39 05 00 00 01 00 00 00 00 00 f3 5b ad bc ...
```

**结论**：微信 4.2 的密钥派生与所有公开方案都不同，进一步突破需要逆向 `Weixin.dll`。

## 3. 内存雕刻（本项目的方案）

微信用来加速查询的**解密后数据页常驻进程内存**，这是突破口。

### 3.1 流程

```
枚举内存区域（VirtualQueryEx + ReadProcessMemory）
  → 按 4096 对齐切页
  → 页头校验：type ∈ {0x0D 表叶, 0x0A 索引叶}
  → 解析 cell 指针数组
  → 每个 cell：varint(payloadLen) + varint(rowid) + record
  → record：varint(headerLen) + serial types + 数据
  → 还原列值（int / float / text / blob）
```

### 3.2 SQLite 记录格式要点

- 行内**第 0 列是 rowid**，不是业务列——这一点极易搞错，早期版本因此把 `T` 形状误算成 `iT`，导致映射表全空
- serial type：`0`=NULL，`1..6`=整数（1/2/3/4/6/8 字节，大端、有符号），`7`=float64，`8`=0，`9`=1，`≥13 奇数`=文本，`≥12 偶数`=BLOB
- 文本/BLOB 长度：奇数 `(n-13)/2`，偶数 `(n-12)/2`

### 3.3 关键表

```sql
chatroom_member(room_id INTEGER, member_id INTEGER, UNIQUE(room_id, member_id))
Name2Id(user_name TEXT PRIMARY KEY)              -- rowid → username
```

拼接方式：`chatroom_member.room_id` 与 `.member_id` 都是 `Name2Id` 的 rowid。

## 4. 数据污染与四道校验

内存里混着**多个数据库**的页，而每个库都有独立的 id 编号空间
（`contact.db` 的 `Name2Id`、`message.db` 的 `ChatName2Id`、`SenderName2Id` 等），
同一个 id 号在不同库里指向完全不同的实体。

实测：2287 个 id 中 **1605 个（70%）存在冲突映射**，例如 `id=538` 对应 4 个不同 wxid。

### 校验规则

| 规则 | 目的 |
|---|---|
| 页面形状一致 | 该页每行都是同样的列型，排除混合页 |
| **主导 id 占比 ≥ 70%** | `chatroom_member` 按 `(room_id, member_id)` 排序，一页内绝大多数行属同一群；散落上百个 id 的页是别的表 |
| 主导 id 必须映射为 `@chatroom` | 排除消息表、索引表 |
| 成员 id 必须映射为 `wxid_*` | 排除消息 id、会话 id 等非人类条目 |
| 群人数 ≤ 500 | 微信群上限，超出视为脏数据 |

效果对比（同一份内存数据）：

```
加校验前：59 个"群" / 1378 条记录（含一个 1248 人的假群）
加校验后：15 个群 / 633 条记录（最大 231 人）
被拒绝的"两整数页"：60 个里拒掉 49 个
```

代价是数字变小，但**留下的每一条都可信**。

## 5. OCR 方案

Windows 自带 OCR 支持简体中文，**无需第三方库、无需联网**。

```powershell
[Windows.Media.Ocr.OcrEngine]::AvailableRecognizerLanguages
# zh-Hans-CN
```

### 三个坑

1. **文件权限**：`StorageFile.GetFileFromPathAsync` 在受限上下文中报 `拒绝访问`。
   → 改用**内存流**：`WindowsRuntimeStreamExtensions.AsRandomAccessStream(MemoryStream)`
2. **小字识别错**：直接识别会把「招」认成「摺」、「询」认成「洵」。
   → **放大 2 倍**（HighQualityBicubic）后识别，结果完全正确
3. **PowerShell 编码**：UTF-8 无 BOM 的脚本会被 PS 5.1 按 GBK 解码，中文吞掉引号导致语法错误。
   → 脚本必须带 BOM

### OCR 的边界

- 微信成员面板里的**昵称本身就被截断**（显示成"张*…"），OCR 也救不回来
- 群成员发言区可以读出发言人昵称，但**小字容易错**（实测某三字昵称被识别成形近字）

## 6. 全自动点击为什么不可行

尝试过三条路，全部失败：

1. **搜索 wxid 加好友**：非好友的 wxid 搜不到（微信不允许）
2. **按昵称在消息区定位头像点击**：OCR 认错名字，且窗口尺寸变化后坐标失效
3. **监听模式（不抢焦点，等你手动点开菜单）**：微信的浮层**一失焦就收起**，
   而用户双击脚本必然导致焦点离开微信

而且盲点坐标有**误操作风险**：调试中曾点到群聊菜单，产生了「你已解散该群聊」，
若点到「删除并退出」则不可逆。

→ 最终采用**半自动**：程序只做两件绝对可靠的事（写剪贴板、置前窗口），点击交给人。

## 7. 其他坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `Start-Process` 启动带 `requireAdministrator` 的 exe 会挂起 | Windows 提权 + PassThru 的已知问题 | 用 `cmd /c start "" "x.exe"` |
| csc 报 `CS0016 文件正被另一进程使用` | 目标 exe 正在运行 | 提权 `taskkill` 后重编 |
| 控制台程序卡死、标题变成「选择」 | QuickEdit 模式选中了文本导致冻结 | 关闭 QuickEdit，或日志写文件 |
| `Get-Process -Name Weixin` 看不到微信 | 提权进程对非提权进程不可见 | 用 `EnumWindows` 枚举窗口 |
| `GetWindowText` 在无响应窗口上阻塞 | 同步发送消息 | `SendMessageTimeout` + `SMTO_ABORTIFHUNG` |
| 中文源码编译后乱码 | 默认代码页 | `csc /codepage:65001` |

## 8. 数据目录

```
%APPDATA%\群好友助手\
├── settings.ini          设置
├── pages-cache.tsv       累积缓存（删除后需重新累积）
├── last-read.tsv         上次读取快照
├── group-labels.tsv      群重命名（群号 → 自定义名字）
├── add-log.tsv           半自动添加进度（用于断点续传）
├── wxid-all.txt          全部微信号
└── cli-read.csv          命令行模式导出
```

**缓存会随每次读取增长**（150k 行 → 350k 行约需 10 次读取），
覆盖率和人数都会随之变化——看到同一份代码两次跑出不同数字时，先检查缓存大小。
